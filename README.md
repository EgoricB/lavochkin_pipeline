# Lavochkin Pipeline

[Открыть интерактивный атлас](https://egoricb.github.io/lavochkin_pipeline/)
· [Читать научный отчёт](docs/research/ntrs-topic-analysis/README.md)

Компактная система воспроизводимой обработки открытых документов
по истории космической техники на Python и PostgreSQL
с экспериментальным ML-планировщиком.

Проект независимый и не является официальной системой НПО Лавочкина
или его музея. Внутренние материалы предприятия не используются.

## Статус

Создан исследовательский прототип: собран корпус, выполнен разведочный тематический анализ, проверены метаданные, проверена чувствительность, получены темы, характерные записи и профили 593 документов.

## Цель и задачи

Цель — разработать небольшой конвейер обработки цифровых коллекций
и проверить влияние прогнозирования длительности заданий на их планирование.

- Гуманитарная задача: сохранять происхождение документов и связь
  исходного материала с результатами преобразования.
- Техническая задача: реализовать зависимые задания, журнал выполнения,
  повторные попытки и восстановление после сбоев.
- Прикладная задача: предоставить интерфейс запуска обработки
  и наблюдения за состоянием коллекции.
- Научная задача: сравнить FIFO и выбор задания по прогнозируемой
  длительности при одинаковых условиях выполнения.

Проект не решает задачу автоматической исторической интерпретации текстов.

## Источники и границы корпуса

Источник — NASA Technical Reports Server (NTRS):
https://ntrs.nasa.gov/

Планируемая тема — миссии НПО Лавочкина 1965–1991 годов.
Период относится к миссиям, а не к датам публикаций:
поздние исследования этих миссий также могут включаться.

Это собственная выборка из архива, а не готовый датасет НПО Лавочкина.
Наличие релевантных материалов подтверждено, но окончательный состав
и объём корпуса ещё не установлены.

Начальная выборка для проверки загрузки и извлечения текста:

| Документ | Идентификатор NTRS |
| --- | --- |
| The Difficult Road to Mars: A Brief History of Mars Exploration in the Soviet Union | 19990054835 |
| Deep Space Chronicle | 20020052429 |
| Soil Mechanics Results of Luna 16 and Lunokhod 1: A Preliminary Report | 19720007196 |
| Magnetic Field in Le Monnier Bay According to Data of Lunokhod 2 | 19780005010 |

Страницы записей: `https://ntrs.nasa.gov/citations/<идентификатор>`.
Исторические обзоры могут охватывать более широкий период:
это отмечается в метаданных, а не скрывается при включении документа.

Отбор проводится по содержанию, а не только по совпадению названия миссии.
Начальная цель — проверить четыре документа, затем при наличии подходящих
материалов расширить выборку ориентировочно до 30–50 PDF.

Для каждого документа сохраняются идентификатор, название, дата публикации,
ссылка на источник, дата получения, основание включения и контрольная сумма.
Условия использования проверяются отдельно: публичный доступ не считается
автоматическим разрешением на перепубликацию.

PDF и производные данные не включаются в Git.
В репозитории допускается манифест с идентификаторами и ссылками.

## Первые результаты

Выполнены сбор материалов NASA NTRS, технический аудит PDF,
объединение файлов с метаданными и предварительная тематическая
разметка названий и аннотаций.

### Объём корпуса

| Показатель | Результат |
|---|---:|
| Записи метаданных | 1 527 |
| Записи с локальными PDF | 604 |
| PDF-файлы | 606 |
| Суммарное число страниц | 24 637 |
| Общий объём PDF | 4,30 ГБ |
| PDF с непустым текстом без зарегистрированных ошибок извлечения | 604 из 606 |
| Точные файловые дубликаты по SHA-256 | 0 |

### Что показал первичный анализ

- Корпус неоднороден по объёму: медиана составляет 8 страниц
  на PDF, среднее — 40,66 страницы, максимум — 1 757 страниц.
  Количество файлов само по себе недостаточно для оценки
  объёма обработки.

- Состав записей с локальными PDF отличается от всей поисковой
  выборки. Например, PDF имеются у 34 из 515 записей типа REPRINT
  и у 104 из 106 записей типа CONTRACTOR_REPORT.
  Выводы по скачанным текстам нельзя автоматически переносить
  на все найденные записи.

- Среди 604 записей с PDF у 215 найдены заданные выражения
  без дополнительных флагов неоднозначности; у 214 обнаружены
  неоднозначные упоминания; у 175 совпадения с правилами отсутствуют.
  Эти статусы описывают работу классификатора,
  а не подтверждённую музейную релевантность.

### Ограничения

Тематические метки предварительные и основаны только на названиях
и аннотациях. Они показывают упоминания, а не обязательно основную
тему документа. Релевантность остаётся UNREVIEWED.
Фильтрация по периоду миссий и анализ по годам публикации
пока не выполнены.

## Обработка

```text
Поиск и отбор метаданных NTRS
    → скачивание PDF
    → извлечение текста по страницам
    → нормализация
    → вычисление характеристик
```

- Исходные PDF сохраняются неизменными.
- Извлечённый и нормализованный текст хранятся раздельно.
- Сохраняется связь текста с документом и номером страницы.
- Нормализация ограничивается технической очисткой пробелов и переносов;
  преобразования должны быть описаны и протестированы.
- Рассчитываются размер файла, число страниц, символов и слов,
  а также доля страниц без извлечённого текста.
- Отсутствие текста или подозрение на неполное извлечение приводит
  к отметке `needs_review`, а не к автоматическому признанию обработки успешной.
- Для этапов фиксируются версия обработчика, параметры, длительность,
  статус и ошибка. OCR в MVP не входит.

## Архитектура

Модульное Python-приложение, один рабочий процесс и одна база PostgreSQL.
Без микросервисов и отдельного брокера сообщений.

```text
CLI / веб-интерфейс → PostgreSQL ← Python-worker
                                      ↓
                                локальная data/
```

| Компонент | Ответственность |
| --- | --- |
| Загрузчик | Метаданные NTRS, скачивание, защита от дублей |
| Обработчик | Извлечение текста, нормализация, характеристики |
| Очередь | Зависимости, статусы, повторные попытки |
| Worker | Выполнение готовых заданий и измерение длительности |
| Планировщик | FIFO или выбор по прогнозируемой длительности |
| ML-модуль | Подготовка истории, обучение, прогноз и оценка |
| Веб-интерфейс | Документы, задания, ошибки и эксперименты |

В PostgreSQL хранятся метаданные и связи результатов.
Основные таблицы: `documents`, `jobs`, `job_runs`, `experiments`.
PDF, текст и артефакты моделей хранятся локально;
в базе регистрируются их пути, версии и контрольные суммы.

Повторный запуск не должен создавать дубли документов или результатов.
После сбоя задание возвращается в обработку по заданной политике повторов.

## Машинное обучение

Регрессионная модель прогнозирует длительность конкретного этапа.
Целевая переменная — измеренное время выполнения; ручная разметка не нужна.

Используются только признаки, доступные до запуска задания:
тип этапа, размер входа и ранее полученные характеристики.
Извлечение признаков также учитывается при оценке стоимости планирования.

ML-планировщик выбирает готовое задание с минимальным прогнозом длительности.
Зависимости этапов соблюдаются при обоих вариантах планирования.
Сравнение точности прогноза включает простой базовый прогноз
по исторической длительности заданий соответствующего типа.

## Эксперимент

Скачивание выполняется заранее и исключается из основного сравнения,
чтобы сетевые задержки не подменяли оценку локальной обработки.

Условия:
- одинаковые документы, зависимости и сценарий поступления заданий;
- один worker и фиксированные версии обработчиков;
- разделение обучения и тестирования по документам;
- все страницы и этапы одного документа остаются в одной части выборки;
- обучение и настройка не используют тестовые длительности;
- фиксированная модель во время тестового прогона;
- повторные измерения с учётом кэширования и фоновой нагрузки;
- отдельный учёт накладных расходов планировщика.

Метрики:
- среднее время ожидания задания;
- среднее время от постановки задания до завершения;
- время до готовности всего документа;
- полная длительность обработки коллекции;
- ошибка прогноза длительности.

Улучшение не предполагается заранее. Перестановка заданий с одним worker
может сократить ожидание, не сокращая полное время обработки коллекции.
Оценивается также задержка длинных заданий.

## Границы MVP

Включены: один архив-источник, фиксированный конвейер,
PDF с извлекаемым текстом, один worker, два планировщика
и небольшой веб-интерфейс.

Не включены: OCR, языковые модели, распределённая обработка,
микросервисы и публичная музейная экспозиция.

Базовые технологии — Python и PostgreSQL.
Конкретные библиотеки и дополнительные технологии согласуются отдельно.

## Ограничения

Четыре начальных документа нужны для проверки реализации,
а не для доказательства эффективности ML.
Корпус из 30–50 PDF остаётся пилотным: его достаточность
и разнообразие оцениваются по результатам измерений.
Повторные запуски одного файла не заменяют независимые документы.

Сканы без доступного текстового слоя требуют отдельного решения
и не считаются автоматически обработанными.
Результаты ограничены выбранным корпусом, оборудованием и условиями запуска.
Синтетические задания допустимы для тестирования сбоев,
но не заменяют основной эксперимент на документах NTRS.
