# Lavochkin Pipeline

Компактная система обработки цифровых коллекций
на Python и PostgreSQL с экспериментальным ML-планировщиком.

Статус: проектирование. Реализация ещё не начата.

## Цель

Разработать воспроизводимый конвейер обработки материалов
цифрового культурного наследия и проверить, помогает ли
прогнозирование длительности заданий сократить время ожидания.

Готовый музейный датасет не требуется: первые эксперименты
проводятся на программно генерируемых документах и нагрузках.

Проект независимый и не является официальной системой
НПО Лавочкина или его музея.

## Задачи

- Гуманитарная: сохранять происхождение материала и связь
  исходного документа с результатами обработки.
- Техническая: реализовать очередь, зависимости заданий,
  повторные попытки и сохранение результатов.
- Прикладная: предоставить веб-интерфейс запуска и наблюдения
  за обработкой коллекции.
- Научная: сравнить FIFO и планирование по прогнозируемой
  длительности при одинаковых условиях выполнения.

## Границы MVP

- Один рабочий процесс.
- Фиксированный конвейер: загрузка, нормализация текста,
  вычисление характеристик.
- PostgreSQL хранит документы, задания, события и результаты.
- Два планировщика: FIFO и по прогнозируемой длительности.
- Простая регрессионная модель обучается на истории запусков.
- Веб-интерфейс: запуск, статусы, результаты сравнения.

Не входят: OCR, языковые модели, микросервисы,
распределённая обработка и публичная музейная экспозиция.

## Архитектура

Веб-приложение → PostgreSQL ← рабочий процесс

Планировщик выбирает готовое задание.
Рабочий процесс выполняет его и сохраняет результат.
После накопления истории обучается модель длительности.

Стек: Python и PostgreSQL.
Веб-фреймворк и ML-библиотека выбираются отдельно.

## Эксперимент

1. Сгенерировать воспроизводимый набор документов.
2. Собрать историю выполнения для обучения модели.
3. На отдельной нагрузке сравнить FIFO и ML-планировщик.
4. Повторить эксперимент с несколькими случайными зёрнами.

Метрики:
- среднее время от постановки задания до завершения;
- среднее время ожидания;
- общее время обработки коллекции;
- ошибка прогноза длительности.

Общее ускорение не предполагается заранее:
изменение порядка заданий может сократить ожидание,
не сокращая общую продолжительность обработки.

## Ограничения

Синтетические нагрузки позволяют проверить реализацию
и гипотезу в контролируемых условиях, но не доказывают
эффективность на реальных музейных коллекциях.

Искусственные задержки используются для проверки сбоев,
а не как единственное доказательство качества ML.
